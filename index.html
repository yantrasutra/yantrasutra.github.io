Etymology

Mechanism and principle

यन्त्र
Yantra / Machine

The apparatus, tool, or engine. Concrete software systems, strict type checkers, test suites, compilers, and automated agent harnesses.

सूत्र
Sutra / Thread

The aphorism, rule, or guiding thread. Explicit specifications, domain models, architectural decision records, and boundary constraints.

Autonomous agents drift when given open-ended tasks and large context windows. Yantrasutra binds execution to formal specifications, verifiable acceptance tests, and strict context budgets.
Standards

Core engineering principles

Constrain upfront
Spend human attention on problem definition, domain language, and test boundaries before writing code. Implementation runs autonomously against explicit acceptance criteria.
Subtract before adding
Remove dead code, premature abstractions, and redundant dependencies before introducing new features. Simpler systems fail less often.
Type system discipline
Enforce sound static typing, discriminators, and exhaustiveness checks. Unchecked type casts used to bypass compiler errors are treated as bugs.
Prove it works
Require execution evidence, test suite outputs, or concrete profiler traces before declaring any task complete. No unverified assertions.
Fix root causes
Shallow patches and defensive try/catch wrappers mask flaws. Trace defects to their source and correct the underlying invariant.
Methodology

The agent engineering cycle

Step 01
/grill-with-docs
Align on the problem and refine domain terminology in the glossary. Read architecture decision records before changing designs.
Step 02
/to-spec
Synthesize the alignment session into user stories, verifiable acceptance criteria, and explicit out-of-scope bounds.
Step 03
/to-tickets
Decompose the specification into isolated, parallel sub-issues with clean dependency edges.
Step 04
Context budget
Enforce token limits (< 150k tokens) to prevent model attention degradation before starting autonomous execution.
Step 05
/implement-spec
Agents implement tasks autonomously against test suites, followed by dual-axis code reviews for standards and spec compliance.
Step 06
/retro
Convert review findings into permanent linter rules, architectural records, and automated regression guards.
